# 小红书科技图文：降敏 + 核实 + 出图

把一条科技素材（链接、视频、讨论帖、专访）做成可直接发布的小红书图文：封面 + 9 页图 + 正文 + 标签。核心原则：**每个数字、每句引语都要能指到原始出处**；不确定就不放或降级表述。**完整准确高于调性公式。****出图必须等用户明确说定稿之后。**

## 1. 读原始材料，不读二手摘要
- 视频：拉字幕（如 yt-dlp 自动字幕）存成带时间戳的文本；讨论帖：用官方 API 拿全量（HN 用 `https://hn.algolia.com/api/v1/items/<id>`）；文章：抓原文全文，含代码块和日志。
- 记录：标题、链接、发布日期、作者/署名、当前热度（标注抓取时间，热度会涨）。
- 原文日志、代码块、脚注里常藏关键数字（例："(331 earlier calls)"），别只读正文。

## 2. 选角度：完整准确优先，调性跟正文
**事实完整、数字和引语准确，高于任何调性公式。** 调性是把已经成立的正文结构翻译成分页，不是先定「这篇要认知差」再削事实去套。套了会歪的比喻、对不上的对比、为了反转而编的「你以为」，一律不用。完整卡片见 [tones.md](tones.md)。

读完素材，先用**一句话**写出这件事真正的结构（假因果 / 新名词必须翻译 / 两难 / 一条链 / 两条路 / 可检查项 / 对读者的同构动作）。那句话是什么，主调性就是什么。不要按表从上往下抢认知差。

文案第一行写死 `主调性：… / 辅：…`（主 1 个，辅 0–2 个）。封面服从主结构；单页装置可以混用（某一页在纠正假因果，才用「你以为 / 其实」）。图片上不印调性名称。

**口吻是辨识度，主调性不是。** 对标 `posts/` 已落盘文案当底，不对标 Max 或其他博主。锁住这些指纹，读者才能认出是你：正文以「我的判断」起头；需要时「先说人话」；3–4 条可核对的点；判断留余地；金句冷静、比喻一次到位；文末出处 + A/B/C。不用「主包 / 卧槽 / WTF / 这事终于来了」。新成篇可以微接口吻，一次只动一处；不要一帖换一套，也不要把「每篇都认知差」当成个人风格。样本见 [tones.md](tones.md)。

**正文结构 → 主调性（匹配，不是抢跑）：**
- 观众已经有一条假因果 → **认知差 / 反常识**
- 抽象词不翻译就听不懂 → **概念降维**（映射成角色/物件，并写清哪里不像）
- 两个合理目标互撕 → **结构性两难**
- 必须先看懂链路 → **机制拆解**（不写可复现的攻防步骤）
- 两条路在比的不是速度 → **对照**
- 能带走 3–5 条可核对项 → **收藏框架**
- 有「你下周会做的同类事」 → **普通人翻译**
- 有真实步骤/实测 → **避坑实操**

已落盘三篇都用过「你以为 / 其实」做部分分页，但 caption 的中心并不都是认知差：刹车篇是对照，MCP 篇是降维 + 接法两难，livenerf 篇是机制拆解且还没有结论。分页装置 ≠ 主调性。

当天热点也按已落盘结构写满分页（封面 + 判断 + 要点 + 收藏卡 + A/B/C），不要改成群聊速评。

信息差、时间线、数字冲击、情绪共鸣、A/B/C 默认做辅。情绪共鸣不独立成篇。本 skill 不做种草盘点、副业变现、无事实情绪稿。

- 普通读者不认识的专有名词不能当主角。
- 概念对比要准确：互补的东西别写成“两派对立”。
- 不要硬把无关的个人项目/实验塞进去；没有真实数据就不提。
- 「你以为 / 其实」只出现在真正纠正假因果的那几页，不要九页全套，也不要为了用它去造假因果。

## 3. 降敏（小红书限流风险）
- 删掉或替换：中美、冷战、军方/国防部/五角大楼、具体政要、威权国家、生物武器、芯片出口管制、政府合同、官司/法律程序、“最领先”等绝对化词。
- 事实可以中性化重述，但不能失真。
- 对文案、图片文字导出、渲染脚本跑敏感词 grep，必须 0 命中。
- 评论区回复也不延伸到上述话题。

## 4. 核实清单
- **英文引语**：对照字幕/原文逐字核对并记录时间戳。自动字幕只能叫“自动字幕转写”。读起来不通顺的口语句，改用中文大意 + “原片 mm:ss–mm:ss”。
- **数字**按出处类型措辞：原文/日志里的 → 直接写；多篇引用的区间 → “常见估算”；某公司实测 → “一家××公司实测”，不嫁接到别家；某人公开表态 → 只写他说了什么；别的产品/场景的实测 → 不放。
- **时间线**：政策/文件有修订就写清楚。
- 文末加“以上根据公开××和××整理”。
- 外部审稿意见也要回原始来源核；审稿给的新数字没有原始链接就不加。

## 5. 文案阶段（定稿前只出文字）
- 小红书不支持 Markdown：文案用纯文本，存为 .txt 并在聊天里给出。
- 结构：第一行 `主调性：… / 辅：…` / 【标题】(≤20 字) / 【图文】逐页文字 / 【正文】/ 互动 A/B/C / 标签 5–6 个。分页骨架跟**正文结构**走，见 [tones.md](tones.md)；有假因果的页才用「你以为/其实」，不要一律全套。
- 每轮修改后重发文字版，直到用户明确说“定稿/可以发/出图”。定稿前不出图。

## 6. 出图（仅在定稿后）
- 用定稿 txt 的文字逐字出图，不改措辞和数字。
- HTML/CSS → Playwright。画布、色板、字号、边距、导出见 [visual.md](visual.md)。**不要另起浅色清新风，也不要按题材换主色。**
- 固定版式：页码默认 `n/9`（定稿写了 8 页就 `n/8`）、底部作者签名（未提供账号则留空）、统一的📌收藏卡和 A/B/C 互动卡。「你以为 / 其实」只出现在纠正假因果的那几页。
- 常用组件：圆角卡片、双栏对比、时间线、金句左边框、箭头流程、胶囊标签。
- 逐张查看：无截断、无缺字；图文比约 4:6 或 5:5，避免整页纯字。出图后若再改字，只重渲改过的页并再跑敏感词 grep。

## 7. 发布后
- 1–2 小时只有个位数阅读：多半触发低推荐，删掉残余敏感表述再发。

## 8. 措辞自检（来自 MCP 篇的修改经验）
- 不自造标签或派别名（如“插座派/手册派”），直接说是哪种做法。
- 技术概念直接用通行英文（MCP、Skill、MCP server），不硬译成可能混淆的中文；“插件”在 agent 语境专指 plugin，不要乱用。
- 圈内人都知道的工具（如 Pi）不加“有个 XX 工具”式介绍。
- 逐页检查有没有重复：一个概念只在一页定义，其他页讲新信息；每页标题要正面回答自己提的问题。
- 同一句或相邻句主语保持一致；一行里同一个词别出现两次。
- 不写“这周”这类会过期的时间词，用“前几天/最近”或具体日期。
- 数字对比要让读者感到量差（如“331 次工具调用 → 一句结论”）。
- 图片上不印调性名称（包括「认知差」）；调性只用于选角度，不印在图上。
